# 离线摩斯电码生成器设计

## 目标

用简洁、可维护的 Python 3.13 源码重建摩斯电码生成器。程序在 Windows 上使用图形界面，完全离线运行，默认输出 MP3，同时支持 WAV 和同步 LRC。

## 范围

保留以下内容类型：

- 随机字母
- 数字长码和数字短码
- 字母数字混合
- 标点符号
- 通联符号
- Q 简语
- 中国呼号
- 全球呼号
- 本地真实呼号表
- 用户输入的自定义文本

删除以下功能：

- MP4 视频生成
- Edge TTS 和 NATO 语音朗读
- 问题反馈邮件
- 所有联网功能

## 用户界面

界面使用 Tkinter，中文显示，单窗口布局。用户可以设置：

- 内容类型
- 每组字符数
- 生成时长
- 摩斯速度，默认 15 WPM
- 音调频率，默认 700 Hz，允许 300 至 1200 Hz
- Farnsworth 有效速度，默认关闭；启用时必须低于字符速度
- 数字长码或短码
- 输出格式，默认 MP3，可选 WAV
- 输出目录
- 自定义文本（选择自定义文本类型时启用）

界面显示生成内容预览、预计时长、进度和状态。生成期间禁用生成按钮，成功后可以打开输出文件夹。程序记住上次设置，配置仅保存在本机的 `%APPDATA%\MorseGenerator\settings.json`。

## 摩斯与音频规则

国际摩斯码表和点划间隔遵循现行 ITU-R M.1677-1：点为一个时间单位，划为三个单位，同一字符内的符号间隔一个单位，字符间隔三个单位，单词或组间隔七个单位。字符速度按 PARIS 约定计算，一个点长为 `1.2 / WPM` 秒。ITU 标准不强制文件格式、采样率、音频位深或音调频率，因此这些参数作为本程序的工程默认值，不标记为 ITU 强制参数。

可选 Farnsworth 模式保持点划的字符速度不变，只扩大字符间隔和组间隔，使整段音频达到用户选择的较低有效速度。有效速度必须小于字符速度；关闭时严格使用 1:3:7 标准间隔。

音频为 44.1 kHz、16 位、单声道正弦波。每段音调加入很短的淡入淡出包络，防止点划边缘产生爆音。音频生成和 LRC 使用同一个时间轴，避免同步漂移。

生成时长用于随机内容模式：逐组生成内容，直到加入当前完整组后的预计时长首次达到或超过目标；因此最终音频最多比目标多一个完整组，不截断点划或字符。自定义文本模式以完整输入为准，生成时长字段不参与裁剪。

## 输出

WAV 使用 Python 标准库 `wave` 写入。MP3 使用 `lameenc` 直接编码 PCM，不依赖 FFmpeg。当前 `lameenc` 提供 Python 3.13 Windows 二进制包，运行和打包后均不需要网络。

每次生成音频以及同名 `.lrc` 文件。文件名包含内容类型、WPM、频率和时间戳；若仍发生重名，则自动追加序号，不覆盖已有文件。LRC 包含标题、制作者、速度和逐字符组时间标签，并显示原文与对应摩斯码。

## 呼号数据与生成规则

程序明确区分两类呼号：

- **真实导入呼号**：用户从本地 TXT 或 CSV 文件导入，程序离线读取、转为大写、去重并过滤明显无效的格式；不读取姓名、地址等无关字段，不上传或联网更新。TXT 每行一个呼号；CSV 自动寻找名称为 `callsign`、`call` 或 `呼号` 的列。
- **模拟训练呼号**：程序按监管规则和国家格式生成，界面及 LRC 中明确标注“模拟呼号，仅供听抄训练”，不得暗示呼号已经正式指配或可用于发射。

中国模拟呼号以工信部现行业余无线电台呼号编制要求为准，由国家前缀 `B`、台站种类字母、分区数字及省级后缀区段组成。实现包含附件中的省份分区和两字母、三字母后缀范围，并排除 SOS、XXX、TTT 以及 QOA 至 QUZ 等可能与遇险或业务缩略语混淆的后缀。规则数据在代码中注明法规来源和版本日期。

全球模拟呼号使用 ITU 国际呼号系列确定国家或地区前缀，再使用该国常见业余呼号结构生成完整呼号。首版内置中国、美国、日本、德国、俄罗斯、英国、加拿大和澳大利亚八个国家的明确规则；“全球混合”从这八组规则中随机选择。DXCC 前缀数据仅用于校验和显示国家，不作为真实呼号存在性的证明。

程序不捆绑从 RadioID、QRZ、HamQTH、DX Cluster 或其他服务抓取的人员呼号数据。内置测试数据只包含虚构样例；真实呼号训练由用户自行导入合法取得的本地文件。

## 代码结构

- `morse_app/core.py`：摩斯转换、时间轴和 PCM 样本生成，不依赖界面。
- `morse_app/content.py`：随机内容、Q 简语及中外模拟呼号生成。
- `morse_app/callsigns.py`：官方规则数据、呼号格式校验和本地 TXT/CSV 导入。
- `morse_app/exporters.py`：WAV、MP3、LRC 写入和安全文件命名。
- `morse_app/settings.py`：本地 JSON 配置的加载、校验和保存。
- `morse_app/gui.py`：Tkinter 界面、后台生成任务和错误提示。
- `main.py`：程序入口。

核心模块仅使用标准库；只有 MP3 导出模块依赖 `lameenc`。GUI 通过后台线程生成文件，避免窗口卡死；线程只返回结果，所有界面更新均由 Tkinter 主线程完成。

## 错误处理

输入为空、数值越界、目录不可写或编码失败时，不产生半成品最终文件，并向用户显示明确的中文错误。输出先写临时文件，完成后再改名为最终文件；如 MP3 编码失败，保留已成功生成的 WAV 临时源并提示其位置，避免用户完全丢失结果。

若未安装 `lameenc` 且用户选择 MP3，程序提示安装方法，但 WAV 功能仍可使用。程序不下载依赖，也不自动联网。

## 测试与验收

自动测试覆盖：

- 字母、数字长短码、标点和通联符号转换
- PARIS 时间规则与组间隔
- Farnsworth 有效速度和间隔扩展
- 随机内容、中国省级呼号区段和八国呼号格式
- TXT/CSV 真实呼号导入、去重与无效格式过滤
- PCM 的采样率、长度、峰值及淡入淡出
- WAV 文件头与音频时长
- MP3 编码的基本可播放文件特征（安装 `lameenc` 时）
- LRC 时间戳与音频时间轴一致
- 参数校验、配置损坏回退和不覆盖已有文件

人工验收包括启动 GUI、逐项切换内容类型、生成 WAV/MP3、播放试听、检查 LRC、确认窗口生成期间不卡死，以及在断网状态下完成全部操作。

## 规范与参考数据来源

- ITU-R M.1677-1，International Morse code，2009，状态为现行。
- ITU Global Administration Data System，Table of International Call Sign Series。
- 工业和信息化部《业余无线电台管理办法》及附件《业余无线电台呼号编制和核发要求》，按实现时可获得的现行版本固化规则。
- GitHub `k0swe/dxcc-json` 的 DXCC 实体与前缀正则仅作辅助参考；其基础数据为 2020 年版本，因此不作为实时权威名录。
